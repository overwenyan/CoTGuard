## 一句话主张

> 语义 CoT trigger 确实把密钥信息写进了推理轨迹，但**基于 trigger 文本相似度的读出方式
> 完全提取不到它**；换用学习式读出可把归因准确率从随机水平提到 3 倍于随机。

---

## 证据链（每一环都有实验编号）

| 环节 | 发现 | 证据 |
|---|---|---|
| 1 | 预印本检测器在**控制长度混淆后等同随机** | EXP-R0：length-matched AUROC 0.543；只数步数即 0.879 |
| 2 | trigger 使轨迹步数 **7.38 → 14.38**，信号大量由长度承载 | EXP-R0 |
| 3 | 用 trigger 文本做归因，top-1 **停在随机水平** | EXP-R1：0.127/0.127/0.137 vs 随机 0.125（三种密钥空间） |
| 4 | 把 pattern 相似度 max 从 **0.897 压到 0.329**，归因**仍不改善** | EXP-R1：可分离密钥空间无效 |
| 5 | **但密钥信息确实在轨迹里**：学习式读出达 **3× 随机** | EXP-R1b：最近原型 0.346/0.404/0.375 vs 随机 0.125 |

**结论**：不是载体没有容量，是**读出方式错了**。第 4 环排除了"密钥空间设计"这一解释，
第 5 环证明信息存在——两者合起来把矛头精确指向读出机制。

## 按模板的四个写作动作

### 动作一：开场锚定真实部署 + 命名资产

推理轨迹在多智能体系统中被中继、被复用；轨迹数据本身成本高昂（ActHook 用 $100/条轨迹
论证过）。资产 = **owner 的 k-引导推理轨迹**。

### 动作二：两层 gap（写成失效模式，不写"没人做过"）

**第一层（整类方法机理上不适用）**：行为层水印（AgentMark / SeqWM / Agent Guide / ActHook）
依赖"从有限候选集中选离散动作"——密钥由构造可分离。CoT 推理**没有候选集、没有可保的每步
分布、载体是连续自然语言**，行为层赖以成立的基质不存在。

**第二层（同类工作在什么条件下会碎）**：引用它们自己的数字——AgentMark 的 Bit Recovery
在语义改写下塌到 **16.84%** 且 Limitations 自认 paraphrasing 是失效模式；SeqWM 把
"semantic paraphrase-style trajectory edits" 列为 future work。收口一句：
**语义改写正是推理轨迹在 agent 间中继时所做的事。**

### 动作三：方法（一个中心 trick）

**学习式密钥读出**替代 trigger 文本相似度：从 owner 自己生成的参考轨迹里学每个密钥的表示，
而非假设密钥的语义会以词汇相似度的形式留在轨迹中。

配套两个必需组件（均由实验逼出，非工程细节）：
- **per-pattern 标准化**（EXP-005）：不同 trigger pattern 对文本有异质固有亲和度
  （sd=0.0299），不消掉则校准彻底失效（KS 0.44 → 0.086）
- **length-matched 评估**（EXP-R0）：不控制则 AUROC 被步数平凡驱动

### 动作四：轻量理论（服务设计选择，不承担新颖性）

参照 PolicyGuard（同组，ICML 2026，理论约一页且部分借用）：给一条说明"为何文本相似度读出
必然次优"的命题即可，不追求渐近最优性。
