# CoTGuard 威胁模型与问题形式化（S3 草稿）

_2026-09-09　目标：可直接改写为论文 Section 3_

本文档修正预印本中**度量与主张错位**的问题：原文声称保护"版权内容"，但 δ 实际测量的是我方 trigger
引导的推理轨迹特征是否留存。以下形式化以后者为准，措辞全程与之一致。

---

## 3.1 参与方与资产

### 参与方

| 符号 | 角色 | 说明 |
|---|---|---|
| `O` | Owner / Verifier | 部署受保护多智能体系统的一方，**持有 trigger key `k` 与映射 `T(·,·)`**。同一实体既注入也验证 |
| `A` | Adversary / Reuser | 未经授权获取并复用 `O` 系统推理轨迹的第三方 |
| `𝒜 = {A_1,…,A_N}` | Agent chain | `O` 系统内串行协作的 agent，`A_i` 接收 `A_{i-1}` 的输出并续写推理 |

### 被保护的资产（**关键定义**）

被保护的**不是**某段版权文本，而是：

> **在 trigger key `k` 引导下产生的推理轨迹分布** `𝒟_k`。

`O` 主张的是**来源（provenance）**：某条候选轨迹是否源自 `O` 的 `k`-引导系统。这与"该轨迹是否复现了
受版权保护的文本"是两个不同命题；本文只主张前者，且实验度量与前者对齐。

> **写作提醒**：全文不得出现"检测版权内容复现"这类表述，只能说"检测 `k`-引导轨迹的未授权复用"。
> 版权保护是该来源检测能力的**下游应用**，应放在 Introduction 的动机段而非技术主张里。

## 3.2 系统模型

给定查询 `q` 与任务类型 `t`，`O` 生成 trigger pattern `τ = T(k,t)`，构造注入提示

```
p̃ = Instruction(q) + τ
```

Agent 链串行执行：`r_0 = A_1(p̃)`，`r_i = A_{i+1}(r_i-1)`，产生推理轨迹
`R = [s_1, …, s_n]`（`n` 个推理步）。

`A` 获取 `R` 后可能经过 `N` 次转述（relay/rewrite）产生候选轨迹 `R̂`。`O` 观测 `R̂` 并判定其来源。

**跳数 `N` 与 agent 数的区别**：`N` 计的是 `R` 离开 `O` 系统后被改写的次数，而非 `O` 内部的 agent 数。
两者在实验中都需扫描，但理论中的 `N` 指前者。

## 3.3 攻击者能力边界

### `A` 能做什么

- **完全读取** 获得的推理轨迹 `R`（包括所有中间步骤）
- **任意改写**：转述、压缩、扩写、翻译、重排推理步
- **施加混淆压力**：向自己的 agent 下达规避指令（见 3.5 的分级）
- **多次中继**：把轨迹在自己的 agent 链上传递 `N` 次
- **黑盒查询** `O` 的系统若其对外开放（可获得更多 `k`-引导样本）

### `A` 不能做什么（**关键假设**）

- **不知道 trigger key `k`，也不知道 `T(·,·)`**。因此无法确定哪些语义特征是标记、哪些是任务本身
  所需——这正是与 BadChain 分野的地方（见 3.6）。
- 不能访问 `O` 的检测器参数与校准集
- 不能修改 `O` 系统内部的 agent（注入发生在 `O` 侧）

### 范围外（显式声明）

- **蒸馏通道**：`A` 用 `R` 微调自己的模型，而非直接复用轨迹。该情形属 radioactivity
  (arXiv:2402.14904) 的范畴，需要不同的检测范式，本文不主张覆盖。
- **协同多方合谋**去除标记
- 对 `O` 系统的可用性攻击

> 本文主攻两条泄漏通道：**轨迹直接复制**与**转述复用**。

## 3.4 检测器模型（持钥验证方）

`O` 作为 verifier 拥有：

1. **trigger key `k` 与映射 `T`** —— 可生成任意多 `k`-引导轨迹作为参考
2. **干净轨迹校准集** `𝒞 = {R^clean_1, …, R^clean_m}` —— 同任务分布、**未注入 trigger**
3. **逐步打分函数** `s(·)` —— 语义相似度（如 Sentence-BERT 余弦）

**可观测量**：仅候选轨迹 `R̂` 的文本。**不可观测**：`A` 的模型内部状态、token 级概率、采样随机数。

> 这是与水印文献的根本差异：后者的 verifier 可重算伪随机数 `ζ_t`（需 token 级白盒访问），
> 因而获得精确零分布；我们只有文本，必须另寻 Type I 控制的来源（→ 共形校准，见 S4）。

## 3.5 自适应攻击分级

沿用 CoT 混淆压力测试（arXiv:2510.19851）的分级思路，按强度递增：

| 等级 | 攻击 | 说明 |
|---|---|---|
| P0 | 无攻击 | 直接复用轨迹 |
| P1–P2 | 通用改写 | 泛泛的转述/摘要（≈ 预印本 Table 4 的水平） |
| P3–P4 | 结构改写 | 重排推理步、改变粒度、换语言 |
| **P5–P7** | **定向规避** | **Guard-Lexicon（回避指定词汇/风格）+ Do-Not-Mention + Monitor-Aware 叠加** |

**最强攻击**为 P≥5 施加在中继 agent 上、针对 external CoT。理由：我方 trigger 活在 external CoT，
而该通道经验上最脆弱（相关工作报告条件混淆成功率 75–90%，internal CoT 仅约 25%）。

**攻击者效用约束**：混淆压力会损害任务成功率（相关工作观测到 32–45pp 下降）。因此评估须报告
**检测率 vs 攻击者任务效用**的前沿，而非孤立的检测率——一个让攻击者付出 40pp 准确率代价的规避
不构成实际威胁。

## 3.6 与 BadChain 的形式化分野（I2）

BadChain (ICLR'24) 论证 CoT 后门难以检测时，其防御方设定为：

> 触发器对防御方**未知**，防御方只能靠通用异常检测（论文中的两种 shuffling 防御据此失效）。

CoTGuard 的设定**在这一点上正相反**：注入方与验证方是同一实体 `O`，`k` 已知。于是：

- BadChain 面对的是**复合假设检验**（触发器未知 ⟹ 需在整个触发器空间上取上确界）
- CoTGuard 面对的是**带密钥的简单假设检验**（`k` 已知 ⟹ 零分布可用校准集刻画）

**这不是"意图不同"的辩解，而是问题类别的改变**：BadChain 的不可检测性论证对持钥验证方不适用，
因而不构成对本文方法的否证。这一段应写进 Related Work 作为正面区分。

> 诚实交代：注入机制本身与 BadChain 高度同构（同为黑盒 prompt 层注入），差异有二——
> (1) BadChain 需污染 demonstration 以绑定 trigger→target 且**必须改变最终答案**，我们只追加 `τ`，
> 两者皆不触及；(2) 上述持钥地位差异。第 (2) 点才是承载理论的那一条。

## 3.7 假设检验的形式化陈述

对候选轨迹 `R̂ = [ŝ_1, …, ŝ_n]`：

```
H0 :  R̂ 的产生过程与 k 独立（未使用 O 的 k-引导系统）
H1 :  R̂ 源自 O 的 k-引导系统，且经历了 N 次转述
```

在 `H1` 下，借用 partial-inheritance 的思路（arXiv:2501.02441），候选分布落在 `𝒟_k` 周围的一个
TV 球内，半径随跳数增长：

```
H1(N) :  TV( 分布(ŝ_t), 𝒟_k,t ) ≤ 1 - θ_N ,     θ_N 随 N 单调递减
```

`θ_N` 随 `N` 递减，且 `θ` 存在使两分布不可分的下界——这**从形式上预示了最大可检测跳数的存在**，
是 S4 定理的出发点。

**检测目标**：在 Type I error ≤ α 的约束下最大化检出功效，并刻画使检测仍可能的最大 `N`。
